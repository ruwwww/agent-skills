# Low-Latency ML Runtime Engineering & Programmatic Dependent Launch (PDL)

Notes and patterns distilled from high-throughput, low-latency CUDA LLM inference runtimes (e.g. `Layr-Labs/cudafast-qwen38-125b-a6b-engine`, `antirez/ds4`).

---

## 1. Programmatic Dependent Launch (PDL) / Stream Serialization (PSS)

Available in CUDA 12.3+ / 13+. Allows consumer kernels to launch on available SMs concurrently with their producer, fetching read-only weights from DRAM into registers *before* producer activations finish computing.

### Mechanism
1. **Producer Kernel (e.g. RMSNorm / Quantize)**:
   Calls trigger early in body:
   ```cuda
   #if __CUDA_ARCH__ >= 900
   cudaTriggerProgrammaticLaunchCompletion();
   #endif
   ```
2. **Launch Configuration**:
   Consumer is launched with launch attribute `cudaLaunchAttributeProgrammaticStreamSerialization`:
   ```cuda
   cudaLaunchAttribute attr;
   attr.id = cudaLaunchAttributeProgrammaticStreamSerialization;
   attr.val.programmaticStreamSerializationAllowed = 1;
   config.attrs = &attr;
   config.numAttrs = 1;
   cudaLaunchKernelEx(&config, consumer_kernel, ...);
   ```
3. **Consumer Kernel (e.g. Projection GEMM)**:
   Issues weight loads into registers, then synchronizes:
   ```cuda
   // 1. Load weights (read-only session slabs, safe to fetch early)
   int32_t w = __ldcs(weight_ptr);

   // 2. Fence before reading producer's activation output
   cudaGridDependencySynchronize();

   // 3. Load activations and compute
   float act = activation_ptr[idx];
   ```

### Critical Hazards
- **Single-Wave Producer Constraint (Deadlock Prevention)**:
  The producer's grid dimension must NOT exceed device SM residency capacity (single wave only). If the producer requires multiple waves, consumer blocks waiting at `cudaGridDependencySynchronize()` occupy SM execution slots needed by subsequent producer waves, causing an irrecoverable hardware deadlock.
- **Compiler Hoisting Trap (`.nc` loads)**:
  `cudaGridDependencySynchronize()` orders acquire semantics, but `ld.global.nc` (generated by NVCC when pointers have `const __restrict__`) is not ordered by it—the compiler can hoist `ld.global.nc` above the synchronization fence.
  **Rule**: Strip `__restrict__` from consumer *activation* pointers. Retain `__restrict__` on *weight* pointers so weight loads are aggressively hoisted ahead of the fence.

## 2. Coarse-to-Fine Vocabulary Screening in Speculative Decoding

At $B=1$ autoregressive decoding, un-embedding / vocabulary projection across large token vocabularies ($V \ge 150\text{k}$) is memory-bandwidth bound.

### 2-Pass Coarse Screening Pattern
- **Coarse Screen (Stage 1)**:
  Evaluate only a fraction of quantization groups (e.g. 24 out of 80 Q8_0 blocks) across the vocabulary matrix to produce approximate scores and shortlist top-$K$ candidates (e.g. 2,048 for draft tokens, 16,384 for target verification).
- **Exact Refinement (Stage 2)**:
  Compute full dot products (all 80 Q8_0 blocks) exclusively on the shortlisted token IDs.
- **Bandwidth Gain**: Drops DRAM transfer volume substantially (e.g. -90.6 MB per decode round) while preserving exact golden-token recall.

## 3. Hardware Primitives & SASS Efficiency

- **Unaligned Byte Slicing (`__funnelshift_r`)**:
  When packing non-power-of-two quantization blocks (e.g. 34-byte Q8_0 chunks: 2-byte scale + 32-byte quants), access addresses often misalign across 4-byte boundaries. Load aligned 32-bit words and extract payload via barrel shift:
  ```cuda
  uint32_t shift = (uint32_t)(addr & 3u) * 8u;
  uint32_t val = (uint32_t)__funnelshift_r(prev_word, next_word, shift);
  ```
- **Cache Eviction Control (`__ldcs`)**:
  Use `__ldcs` (Load Cache Streaming / evict-first) for one-pass weights to prevent displacing persistent states (KV cache, recurrent states, attention tape) from L1/L2 caches.
- **Vectorized Accumulation (`__dp4a`)**:
  Compute 4-element int8 dot products into int32 in a single instruction:
  ```cuda
  dot = __dp4a(weight_q4, act_q4, dot);
  ```
- **Register-Direct Reduction (`__shfl_xor_sync`)**:
  Perform intra-warp reduction across lane pairs directly in registers, avoiding shared memory allocation, staging latency, and bank conflicts.

## 4. Resident Process Architecture for Test/Bench Harnesses

- **Weight Residency**: Multi-gigabyte weights (e.g. 100+ GB) must be owned by a persistent daemon (`ds4-resident`) serving over a local Unix domain socket (`AF_UNIX`).
- **In-Band Frontier Argmax**: State-mutating commands (`eval`, `sync`, `eval_speculative`) return the argmax token directly in the response payload. Avoids separate socket roundtrips for argmax queries, reducing per-token decode overhead to a single IPC roundtrip (<0.3 ms).
- **Replay Disagreement Tracking**: Count divergence between batched verification (row-0) and serial single-row replay (`verify_replay_disagreements`) to detect batch-invariance issues in exotic architectures without crashing benchmark loops.
